# Font Analysis App - Development Context

## Project Overview

React + Express app for scanning, storing, analyzing and comparing font files. Uses opentype.js for parsing, Vite for bundling, Tailwind for styling. Server runs on port 3001, Vite proxies `/api` requests to it.

## Architecture

- **Server** (`server/`): Express API with JSON file database (`fonts-db.json`) and Google Fonts starter DB (`google-fonts-db.json`)
- **Client** (`src/`): React SPA with routes for Library (`/`), Analyze (`/analyze/:fontId?`), Compare (`/compare?ids=...`)
- **Analysis** (`src/analysis/`): Stroke contrast, x-height, proportions, weight, spacing analysis modules
- **Font parsing**: opentype.js (supports TTF, OTF, WOFF); wawoff2 for WOFF2→TTF decompression

## Key Data Structures

```typescript
interface StoredFont {
  id: string;              // UUID
  filePath: string;        // Absolute path on disk
  fileName: string;
  familyName: string;      // From font metadata (name ID 1)
  preferredFamilyName?: string; // From name ID 16 (typographic family)
  subfamilyName: string;   // e.g. "Regular", "Bold", "Italic"
  weight: number;          // OS/2 usWeightClass or inferred
  style: 'normal' | 'italic' | 'oblique';
  format: string;          // 'otf' | 'ttf' | 'woff' | 'woff2'
  fileSize: number;
  glyphCount: number;
  unitsPerEm: number;
  ascender: number;
  descender: number;
  lastModified: string;
  addedAt: string;
  metrics?: { contrast: number; weight: number; width: number; xHeight: number };
  category?: 'serif' | 'sans-serif' | 'monospace' | 'display' | 'script';
  categoryOverride?: 'serif' | 'sans-serif' | 'monospace' | 'display' | 'script';
  tags?: string[];
  isVariable?: boolean;           // True if font has fvar table with axes
  variableAxes?: VariableAxis[];  // { tag, minValue, defaultValue, maxValue, name }
}
```

Database: `{ version: 1, fonts: StoredFont[] }` in `fonts-db.json`, atomic writes via `.tmp` rename.

## API Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/pick-folder` | Native OS folder picker |
| GET | `/api/scan-stream` | Streaming scan (NDJSON), accepts `source` query param |
| POST | `/api/scan` | Non-streaming scan, accepts `source` body param |
| GET | `/api/database` | Get DB metadata |
| POST | `/api/database` | Overwrite DB |
| DELETE | `/api/database` | Wipe DB + all .b64 files |
| POST | `/api/database/dedup` | Retroactive deduplication |
| POST | `/api/database/compute-metrics` | Compute/recompute metrics + category + SVGs for all fonts |
| GET | `/api/fonts/:id/file` | Serve font binary from disk |
| GET | `/api/fonts/:id/data` | Get font base64 data (read from disk on-the-fly) |
| PUT | `/api/fonts/:id/path` | Update file path |
| PUT | `/api/fonts/:id/refresh` | Re-read from disk |
| DELETE | `/api/fonts/:id` | Delete font |
| PUT | `/api/fonts/:id/category` | Set category override for one font |
| PUT | `/api/fonts/bulk-category` | Set category override for multiple fonts |

### Plan 15: Pre-compute Analysis at Import Time

1. **Server-side full analysis** -- New `computeFullAnalysis()` in `server/scanner.ts` computes all 5 analysis results (contrast for `o`/`O`, x-height, proportions, weight, spacing) using pure math at scan time. No DOM or Canvas dependency. Contrast uses polygon flattening + nearest-point distance (same algorithm as `computeFontMetrics()` but enhanced to return `thickestSample`/`thinnestSample` with coordinate points). Weight uses polygon area ratio (shoelace formula) with synthetic pixel equivalents. x-height, proportions, and spacing are identical to the client-side pure-math implementations. Helper `computeContrastForGlyph()` samples 120 points along the outer contour polygon.
2. **`analysis` field on StoredFont** -- Added `analysis?: FullAnalysis` to `StoredFont` (server) and `StoredFontMeta` (client). `FullAnalysis` type imported from `src/types/index.ts` into `server/database.ts`. `ContrastResult.allSamples` is stored as `[]` (not needed by any view). `tsconfig.server.json` updated to include `src/types/index.ts`.
3. **Scan-time integration** -- `scanFont()` now calls `computeFullAnalysis(font)` alongside existing `computeFontMetrics()` and stores the result in `meta.analysis`. All newly scanned fonts include pre-computed analysis.
4. **Retroactive computation** -- `POST /api/database/compute-metrics` now also computes `analysis` for fonts missing it (alongside existing metrics, category, and SVG extraction).
5. **AnalyzeView uses stored analysis** -- Merged the two separate `useEffect`s (font data loading + database fetch) into one `Promise.all` call. When the stored font has `analysis`, it's used directly (no client-side computation). 6. **ContrastView accepts pre-computed xHeight** -- Added optional `xHeight?: XHeightResult | null` prop to `ContrastView`. When provided, skips inline `analyzeXHeight()` call. AnalyzeView passes `analysis?.xHeight` to ContrastView.

### Plan 16: Analysis Fixes & Semi-Advanced Filters

1. **Fix .notdef glyph analysis bug** -- `computeFontMetrics()`, `computeFullAnalysis()`, `isMonoByWidths()`, and `detectSerifFromGlyph()` in `server/scanner.ts` now check `glyph.index === 0` to skip `.notdef` glyphs. ## Known Patterns / Gotchas

- **URW fonts / super-family grouping**: Family names like "BodoniURWExtBol" are abbreviated; `preferredFamilyName` has the clean version ("Bodoni URW"). For fonts WITHOUT preferredFamilyName, `inferPreferredFamily()` in the scanner splits the CamelCase familyName and strips known abbreviation tokens from the end to infer one. `parseAbbreviatedSubfamily` handles compound tokens (Ext+Nar → "Extra Narrow", Ext+Bol → "Extra Bold"). URW families with width in the preferredFamilyName (e.g., "Bodoni URW Narrow") are merged into a super-family via `stripTrailingQualifiers()`. `groupByFamily()` uses `superFamilyName()` as the grouping key.
- **URW abbreviation tokens**: All token maps are now in the shared `src/lib/fontNameTokens.ts`. Scanner and client both import from it. `splitCamelTokens()` handles acronym boundaries: `([A-Z]+)([A-Z][a-z])` splits "URWExt" → "URW Ext".
- **Alfabet/Bungee font type grouping**: `TRAILING_TYPE_NAMES` includes Alfabet types (Liniowy, Kontury, Cieniowany, Kropki, Pisany, Kratki, Linie, Litery, Strzalki) and Bungee visual variants (Layers Rotated, Layers, Inline, Outline, Shade, Color, Shadow). Stripped by `stripTrailingQualifiers()` for super-family grouping. `widthQualifier()` returns the type name so it appears as a version tab in the Library. `TYPE_TOKENS` set exported for diff token validation.
- **Typographic subfamily (name ID 17)**: Scanner reads `font.names.preferredSubfamily?.en ?? font.names.typographicSubfamily?.en` and uses it as subfamilyName when the font's name ID 2 is generic "Regular"/"Normal". This is critical for fonts like Lato where all variants have name ID 2 = "Regular" but name ID 17 = "Thin", "Light", "Bold", etc.
- **woff2 fonts with placeholder names**: Some web fonts have familyName "." -- handled by filename fallback + `isUsableName` requiring 2+ letters
- **American Auto-style fonts**: When `subfamilyName` is "Regular" but `familyName` contains abbreviated weight/style (e.g., "Bld It"), scanner post-processes to set proper `subfamilyName` ("Bold Italic") and `style` ("italic"). Requires re-scan of existing data. Additionally, `inferStyle()` now detects abbreviated tokens directly via `/\bIt\b/` and `/\bObl\b/` regex, catching subfamilyNames like "Bold It" or "Thin Obl" even without the `parseAbbreviatedSubfamily` path.
- **OTF vs TTF weight differences**: Same font can report weight 405 (OTF) vs 400 (TTF) -- dedup uses subfamilyName instead of weight
- **opentype.js Y coordinates**: `getPath()` returns screen coords (Y-down), no manual Y-flip needed
- **Scanner is async**: `scanFont()` and `scanFolder()` return Promises due to wawoff2 async decompress
- **Width qualifier filtering**: `widthQualifier()` computes diff via `computeFamilyDiff()`, splits on CamelCase boundaries, pre-matches compound tokens (e.g., "Demi Bold", "Extra Bold" against `WEIGHT_TOKENS`, `WIDTH_TOKENS`, `TYPE_TOKENS`), validates all tokens against known sets, then filters weight/style tokens to isolate width/type names. Returns `''` if any token is unrecognized.
- **Category classification multi-layer**: `classifyFont()` uses a priority chain: (1) `isFixedPitch`/width uniformity → monospace, (2) **`classifyByStrongName()`** — strong keyword check (serif/slab/bodoni/garamond → serif, script/handwrit/brush → script, display/stencil/shadow/inline/outline/awesome/icon/color → display; skips names containing "sans"), (3) `sFamilyClass` for explicit classes, (4) PANOSE bytes for serif/sans-serif/monospace/script/display, (5) serif detection via capital 'I' glyph path analysis, (6) contrast heuristic (< 0.4 → serif, > 0.85 → sans-serif), (7) **`classifyByName()`** late check (script/mono/display/serif/sans keywords), (8) `display` as ultimate fallback.
- **Category override**: `categoryOverride` field on `StoredFont` takes precedence over auto-detected `category`. UI shows colored category badge on FamilyCard header and AnalyzeView header; clicking opens popover to change. Bulk edit mode allows applying category to multiple families at once. `familyMetrics` in LibraryView uses `categoryOverride ?? category` for effective category in filtering. Overrides persist in `font-overrides.json` (separate from `fonts-db.json`) keyed by `familyName + "\0" + subfamilyName`, surviving library clears and rescans. `mergeFonts()` also carries forward overrides from existing entries. `applyOverrides()` is called after scans, compute-metrics, and Google fonts DB loading to restore user overrides.
- **Font tags**: `tags?: string[]` field on `StoredFont`. Managed via `PUT /api/fonts/:id/tags` (set) and `PUT /api/fonts/bulk-tags` (add). `GET /api/tags` returns all unique tags for auto-suggest. Bulk edit bar allows adding tags to multiple families. Tags also persist in `font-overrides.json` alongside category overrides.
- **Star/favourite system**: Per-family starring via `starredFamilies` array in `FontDatabase`. Keys are plain `familyName` (e.g., `Roboto`). Previously used `source:familyName` format — old keys are auto-migrated at load time by stripping `local:` / `google:` prefixes. Toggled via `PUT /api/starred-families` with `{ key }` body. `groupByFamily()` populates `FontFamily.starred` from the set. Star button in FamilyCard header and GridFamilyCard corner. Optimistic UI updates with rollback via `starredRef`.
- **Saved font paths**: `font-paths.json` (gitignored) stores an array of folder paths. `GET/POST/DELETE /api/font-paths` endpoints. Shown as clickable chips in the scan dialog. Current path can be saved with a "+ Save this path" button.
- **Source-agnostic family grouping**: `groupByFamily()` groups by `superFamilyName` only (no source in key). Same-named local and Google fonts merge into one family card with a combined style count. `FontFamily.sources` lists all sources present; `FontFamily.source` is the dominant source (local if any local fonts present). `variantKey()` in dedup still includes `source` for deduplication purposes (local and Google variants are distinct). AnalyzeView family member search is source-agnostic.
- **Google Fonts download (removed)**: The download-from-Google-Fonts-website functionality (`server/googleFonts.ts`, download panel, API routes) has been removed. Google fonts are now only available via the pre-built `google-fonts-db.json` loaded by `readGoogleFontsDb()`.
- **Analyze recategorization**: Category badge in AnalyzeView header opens a popover to change category for the entire font family. Uses `bulkSetCategory()` on all family members. Category overrides persist via `font-overrides.json`.
- **Pre-computed analysis**: All 5 analysis results (contrast for o/O, xHeight, proportions, weight, spacing) are computed server-side at scan time via `computeFullAnalysis()` and stored in `StoredFont.analysis`. AnalyzeView uses stored analysis directly when available (no client-side computation needed). Falls back to lazy per-tab client-side analysis for uploaded fonts or old data without analysis. Contrast uses pure-math polygon flattening (120 sample points, nearest-point distance) — produces slightly different values than the old SVG DOM approach but is more deterministic and works in Node.js. Weight uses polygon area ratio (shoelace formula) instead of canvas pixel counting. `ContrastResult.allSamples` is stored as empty array (not used by ContrastView).
- **Histogram filtering pipeline**: Histograms avoid circular dependency by splitting filtering into stages: search + category → `searchAndCatFiltered` (used for histogram overlay values) → histogram range filters → `filteredFamilies`. The background chart shape comes from all families; the bright overlay shows only the search/category-filtered subset.
- **Raw metadata extraction**: `extractRawMetadata()` in AnalyzeView reads raw font tables via `font.tables` and `font.names` (cast to `any` to access non-typed fields). Decodes OS/2 `usWidthClass` (1-9 → name), `sFamilyClass` (upper byte class + lower byte subclass), `fsType` (bitmask → permission strings), `macStyle` (bitmask → Bold/Italic/etc. flags). Dates from `head.created`/`modified` are Unix epoch seconds × 1000.
- **GlyphsView web font rendering**: Uses URL-based CSS `@font-face` via `/api/fonts/:id/file` endpoint. `useGlyphFontFace()` hook injects @font-face pointing to the font file URL, uses `document.fonts.load()` for reliable detection, caches by font ID. `GlyphCell` renders characters as `<span>` styled with the web font. Falls back to "?" for glyphs without Unicode codepoints. `GlyphsErrorBoundary` wraps the view for crash recovery.
- **Font serving from disk**: No more base64 backup files. `GET /api/fonts/:id/file` streams font binary directly from `font.filePath` with proper Content-Type and immutable cache headers. `GET /api/fonts/:id/data` reads from filePath on the fly (with woff2 decompression via wawoff2). `compute-metrics` also reads from filePath. If the file doesn't exist on disk, 404 is returned.
- **SVG glyph preview**: During scanning, `extractGlyphSvgs()` pre-extracts SVG path data for A, a, o, O, H, x, n glyphs. Stored in `StoredFont.glyphSvgs` as `{ d: string; advWidth: number }` per character. Library grid view uses `SvgPreview` component to render "Aa" as inline SVG from these pre-extracted paths, avoiding the need to load the full font file for grid previews. Falls back to @font-face loading if glyphSvgs are missing.
- **Google Fonts repo**: Cloned `google/fonts` repo (shallow, `--depth=1`) into `google-fonts/` (gitignored, ~8 GB). Contains ~3857 font files across `ofl/`, `apache/`, `ufl/` directories.
- **Google Fonts starter DB**: `google-fonts-db.json` (committed, ~21 MB) contains pre-scanned metadata for 3580 Google Fonts with metrics, categories, and SVG vectors. Built by `server/buildGoogleFontsDb.ts` (`npm run build:google-db`). Uses relative file paths (e.g., `ofl/roboto/Roboto-Regular.ttf`). Read-only at runtime.
- **Google Fonts DB loading**: `readGoogleFontsDb()` reads and caches `google-fonts-db.json` (60s TTL), resolving relative paths against `google-fonts/` repo location, and applies user overrides from `font-overrides.json`. `findFontById()` searches both local and Google DBs. `GET /api/database` returns merged local + Google fonts. `PUT /api/fonts/bulk-category` handles both local and Google font IDs. If the repo folder doesn't exist, paths remain relative (font files inaccessible but metadata is browseable).
- **Source filter**: Library filter bar has Local/Google pill buttons (green highlight) between Starred and Category filters. `selectedSource` state filters by `family.sources?.includes()` (supports mixed-source families). Included in "Reset all" logic. Filtering pipeline: source → starred → search → category → histogram ranges.
- **CompareView color consistency**: Canvas rendering iterates the full `fonts` array (skipping non-visible entries) to preserve the original index for `COLORS[i % COLORS.length]`. Previously used `visibleFonts.forEach` which shifted colors when fonts were toggled off.
- **Non-Latin font analysis (.notdef fix)**: `font.charToGlyph()` in opentype.js always returns a glyph object (never null) — for missing characters it returns `.notdef` (index 0). All analysis functions now check `glyph.index === 0` and return null/skip for `.notdef` glyphs. This means non-Latin fonts (e.g., Aksara Bali Galang, CJK-only fonts) correctly get null metrics/analysis instead of meaningless data.
- **Script/language support**: `detectScriptSupport()` iterates all font glyphs, counts Unicode codepoints per script range, and reports supported scripts when the count exceeds a per-range threshold. 17 ranges defined (Basic Latin through Vietnamese). Stored as `scriptSupport?: string[]` on `StoredFont`/`StoredFontMeta`. Fonts without any detectable scripts (e.g., Aksara Bali Galang — its Balinese script range isn't in the 17 defined ranges) have no `scriptSupport` field. The "Exclude basic-Latin-only" filter keeps fonts without `scriptSupport` data (tolerant of missing data).
- **Semi-advanced filters**: Style count (min/max number inputs) and language/script filters (exclude basic-Latin-only checkbox, require-script multi-select pills) are shown in the Advanced Filters section. All are included in the "Reset all" logic. Script pills show only scripts detected across the loaded font database (`availableScripts` useMemo).
- **Grid centering**: Library grid view uses `auto-fill` with `minmax(240px, 320px)` and `justify-content: center`. Larger card size accommodates variable font axis sliders and interactive controls. Cards center horizontally when fewer cards than a full row remain after filtering.
- **Playwright env variable**: The Cursor sandbox sets `PLAYWRIGHT_BROWSERS_PATH` to a sandbox-specific temp dir. Tests must run with `unset PLAYWRIGHT_BROWSERS_PATH` or outside the sandbox (`required_permissions: ["all"]`) to find the installed browsers at `~/Library/Caches/ms-playwright/`.
- **Variable font support**: Scanner detects `fvar` table via `font.tables.fvar` (cast to `any`), extracts axes data (tag, min, default, max, human-readable name). `isVariable` and `variableAxes` stored on `StoredFont`/`StoredFontMeta`. `FontFamily.hasVariable` computed by `groupByFamily()` via `members.some(f => f.isVariable)`. Library shows teal "VF" badge on family cards (both list and grid views). "Variable only" checkbox in advanced filters filters by `hasVariable`. AnalyzeView extracts axes from parsed font's fvar table, shows interactive range sliders with live CSS `font-variation-settings` preview, and displays axis info (name, min–max, default) in sidebar. `compute-metrics` endpoint populates variable fields for existing fonts.
- **Variable font reanalysis strategy**: Server-side analysis (`computeFullAnalysis()`) runs at the font's default axis values only. opentype.js reads default outlines and does not natively support rendering at arbitrary axis values; the browser's font renderer handles variation via CSS `font-variation-settings`. For true multi-point analysis at different axis positions, a font rendering engine with variation support (e.g., HarfBuzz via WASM) would be needed — this is a future enhancement. Current approach: analysis at defaults, live CSS preview for visual exploration. The DB size remains manageable and analysis runs fast.
